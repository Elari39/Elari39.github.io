## 这是什么

一个本地桌面文档保险箱。构建阶段把 Markdown / PDF 加密并嵌入应用，运行时只有**密码正确、且本机设备在 MAC 白名单内**才会解锁目录；用户点击某篇文档时，才按需解密这一篇的正文。

它面向的不是「把文件放到服务器上」，而是**把内容、查看器和基础防护一起打包进一个 Windows exe**：分发离线学习资料、内部文档、课程笔记，或者任何需要一层基础访问控制的只读资料包。

## 工作流

```text
构建期                                运行期
──────                                ──────
content/plain/*.md|*.pdf              用户输入密码
        │                                    │
        ▼                                    ▼
access.yaml（密码 + MAC 白名单）      校验本机 MAC ∈ 白名单？
        │                                    │ 否 → 「本机未授权」
        ▼                                    │ 是
cmd/packdocs 加密 ───────────────▶    校验密码 → 解锁目录
        │                                    │
        ▼                                    ▼
internal/vault/generated.go           点击文档 → 按需解密单篇正文
（编译进 exe）
```

`generated.go` 是构建产物、不随仓库提交：克隆之后先执行一次打包命令生成 vault，再构建应用——这样仓库里不会留下任何加密后的内容，也不会留下密码。

## 几个刻意的选择

**每篇独立加密，PDF 分块。** PDF 可能比 Markdown 大很多。按 1 MiB 明文块分块加密、前端按块加载，避免在 Go 侧一次性解密整份文件；前端查看时再拼接成完整 PDF。

**密码不进入二进制。** 构建期密码只用于派生密钥，运行时由用户输入、Argon2id 派生后解密。仓库里只有 `access.example.yaml` 这样的占位符文件，真实配置被 `.gitignore` 挡在外面。

**远程图片默认禁止。** 文档里的 http/https 图片默认不加载，避免打开文档时向图源泄露 IP 与阅读行为；确需在线图片时再显式开启。

**链接协议消毒与 CSP。** 渲染 Markdown 时只保留 `http/https`、`mailto` 与相对路径，`javascript:`、`data:`、`vbscript:` 等协议会被清除；生产构建再注入 `script-src 'self'`、`connect-src 'self'`、`object-src 'none'` 的 CSP 作为第二道防线。

**解锁失败限速。** 连续 5 次密码错误进入冷却（约 30 秒起、随失败次数递增，最长约 8 分钟），抑制在线暴力猜解——但离线爆破仍取决于密码强度。

## 安全边界（如实说明）

这是**访问增强**，不是 DRM，也不是不可破解的内容保护系统：

- `ContentProtectionEnabled` 依赖操作系统与 WebView2 的能力，**不能保证阻止所有截图与录屏**。
- 禁用右键、复制、选中与常见快捷键只提高普通复制的成本，挡不住调试工具、管理员权限工具、驱动级工具或逆向分析。
- MAC 白名单以明文编译进 exe，可被静态提取；网卡 MAC 本身也可以被伪造。它是访问增强，不是 DRM。
- 解密后的正文与渲染结果在解锁会话内以进程内存形式存在。锁定时密钥与缓冲区会被主动清零，但 Go 字符串不可变、无法即时清零，明文副本需等待 GC 回收。
- **划词 AI 解读会突破纯本地边界**：选中的文档片段会发送到所配置的 LLM 端点。对话历史只保存在解锁会话内存里，锁定或关闭即清空。
- AI 凭证以明文编译进 exe，**不受 vault 密码保护**，可被 `strings` 之类的工具提取——所以不应在其中嵌入高价值、长期有效的凭证。
