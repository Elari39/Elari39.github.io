一、约束基线：还剩下多少空间

这个仓库把「能被检查的承诺才算承诺」写进了规矩：所有滚动特效最终都要过 pnpm verify 与 pnpm verify:browser。所以先量清楚余量—— 下面三个数字直接读取自已构建的 dist/，测量口径来自 scripts/budget.mjs。

预算余量（基线：本地已构建的 dist/）
指标 契约上限 当前占用 剩余余量 对新增特效的含义
CSS 未压缩总量 48 KB 43.2 KB ≈ 5.9 KB 新增样式建议合计 ≤ 3 KB，留一半缓冲给后续主题与修复。
交互脚本 raw < 4096 B 3745 B ≈ 351 B 这是最紧的一条。超过它 Astro 就改吐外链脚本，同时踩中「外链 JS 必须为 0」。因此新特效一律零 JS。
客户端 JS gzip ≤ 4096 B 1699 B ≈ 2.4 KB gzip 看似宽松，但被上一条 raw 阈值卡死，实际不可动用。
首页 HTML ≤ 60 KB 51.8 KB ≈ 9.6 KB 有空间放少量装饰性 DOM（如收束层、滚动提示）。
结论先行：特效必须走「CSS 滚动时间线 + 渐进增强」这条路—— 零脚本、零请求、零行内 style。任何需要滚动监听或状态计算的方案（scrollspy、 数字滚动）在当前 JS 余量下都要先做瘦身，本方案默认排除。

必须同时遵守的 4 条红线

  • 进场只动 transform，绝不动 opacity。 .reveal 的每一条规矩都源于此：半透明正文过不了对比度，且时间线未活跃时 「从 0 起跑」等于内容永久隐身。浏览器验收会逐个断言收敛到终态。
  • 不得给 position: sticky 元素的祖先加 transform。 祖先的 transform 会新建包含块，直接废掉页头与阅读页目录的吸附。
  • animation-timeline 必须单独一行声明，不并进 animation 简写。 Lightning CSS 会把简写压成 Chrome 解析不了的形式，整条动画静默失效。
  • 每条动效都要包在 (prefers-reduced-motion: no-preference) 里， 并配 @supports (animation-timeline: …)。 base 层那条全局兜底只管 *::before/::after，管不住滚动时间线， 也管不住 ::view-transition-*。

三、落差：缺的是「分层编排」

把上表横向读一遍，能看出一个共同特征：现有动效都是单层、单元素、单属性的—— 一块内容浮一下、一条线走一下、一个环亮一下。它们各自成立，但彼此之间没有关系， 滚动过程中没有「景深」，也没有「事件」。这正好是「惊叹感」与「沉浸感」的来源：

  • 节奏感——相邻元素按序、错峰地进入，而不是整齐划一地出现。
  • 景深感——前景（文字）稳定可读，中景（卡片封面、图版）随滚动位移，背景（底纹）缓移。
  • 连续性——页面之间不是切换，而是同一个物件被「翻」过去。

下面 9 项建议按这三条落差组织，并严格落在「纯 CSS + 零 JS + 预算内」的框里。

四、新增特效建议（9 项）

每项给出：落点（改哪个页面/区块）、机制（怎样实现）、 优先级（P0 先做 / P1 结构增强 / P2 打磨）、预算（CSS 字节量级）、 收益（读者拿到什么）、守卫影响（会不会动到验收）。

E1 · 条目卡片错峰入场 + 封面纵深视差

P0 首页 #entries

现在 4 张卡片以完全相同的节奏、相同的 12px 上浮进场。改为按序错峰： 用 :nth-child() 给每张卡一个更大的 animation-range 起点，形成一道由上到下的波。同时给卡片内部加纵深——封面的纹样与水印数字 用 view() 驱动轻微横向位移，卡片经过视口中心时最快、到边缘时归位。

机制
外层沿用 .reveal（只动 transform）；错峰靠逐条 animation-range 覆盖，或引入 --stagger 变量配合 calc()。 封面纵深作用在 .cover::before 与 .cover-numeral—— 它们目前是静态纹样，加 transform 不改布局、不动对比度。
预算
≈ 250–450 B CSS · 0 JS
收益
首屏以下第一个「呼吸点」：列表从整齐地浮变成逐张翻开，是低成本高感知的一档。
守卫影响
无。.reveal 仍只动 transform，收敛终态断言照旧通过； 卡片外层不是 sticky 祖先。

E2 · 详情页图版「显影」进场

P0 projects/[slug] #plates

详情页的截图现在就是一块贴上去的图。给每个 figure.plate-figure 一个 view() 时间线：进入视口时从 scale(0.97) 舒展到 1， 描边与柔光同时点到自己条目的强调色（读现有的 --entry-accent）——像照片在显影液里慢慢清晰。

机制
animation-timeline: view(); animation-range: entry 0% entry 60%;， 动画只写 transform: scale() 与 border-color / box-shadow。建议不用 filter 或 mask：前者会强迫每帧重绘整棵子树，后者在滚动中不便宜。
预算
≈ 300 B CSS · 0 JS
收益
详情页最强的沉浸点：图版不再是「文档插图」，而是随滚动显影的一页魔典。
守卫影响
注意 390px 窄屏不得横向溢出（scale ≤ 1 天然安全）； 图片真实宽高不改，跳版断言不受影响。

E3 · 序言印记「苏醒」强化

P0 首页 hero · SigilPlate

印记已经会「显影」，但只有 opacity。再补两笔：外圈那条虚线环用 stroke-dashoffset 随滚动把描边画出来（像阵在成形）， 光晕 .hero-sigil__aura 随滚动放大并提亮。这是面试官第一眼看到的区块， 值得做成一次「开场仪式」。

机制
新增的滚动驱动量必须落在尚未被占用的属性/元素上： 刻度环与符文层已被旋转占用 transform，只能继续动 opacity； 缩放/位移改由 .hero-sigil__aura 与虚线环的 stroke-dashoffset 承担。全部限定 min-width: 48rem （窄屏印记在正文下方，页面高度不保证能滚）。
预算
≈ 200–350 B CSS · 0 JS
收益
首屏即叙事：阵在读者面前逐步成形，把「魔典」的主题在第一秒立住。
守卫影响
只动装饰层，不承载文字；48rem 门限沿用现有写法，窄屏仍是可见终态。

E4 · 卡片 → 详情页 共享元素过渡

P1 跨页 · 最高「哇」值

站点已经开了跨文档视图过渡，但只是根快照淡出——页面之间没有连续性。 给卡片的标题与字形标记和详情页头部的标题配同一组 view-transition-name: entry-<slug>，于是点「翻开这一条」时， 标题不是「跳过去」，而是从卡片位置飞进详情页头部——同一本书翻页，而不是两个页面。

机制
名字由构建期的 slug 类名生成（.entry-card--<slug> 之类）， CSS 里设 view-transition-name，两个页面各声明一半。 不写行内 style，因此不触碰 CSP。命名组与 ::view-transition-group(){animation:none} 的用法， .reading-progress 已经示范过。
预算
≈ 200–400 B CSS · 0 JS
收益
这是最能被记住的一项：面试官点一次就能看到「机制感」—— 说明作者真正理解跨文档视图过渡，而不仅是会用模板。
守卫影响
需要新增浏览器断言（否则等于「写了但没人验证它生效」）： 断言目标页存在同名快照组、且 reduce 下退化为普通导航。 现有 reduce 块已经 animation: none !important 关掉全部 ::view-transition-*，新组会自动被覆盖，但必须实测确认不残留。

E5 · 详情页章节吸顶

P1 projects/[slug] 正文 h2

长文详情页里，读者常常滚到一半就不知道自己在第几节。把正文的 h2 做成吸顶章节头（position: sticky）， 吸附在页头下方，并配一道余烬分隔线——「可翻的魔典」的隐喻由此落到实处。

机制
纯 position: sticky，零 JS。关键约束：该元素不能有带 transform 的祖先（所以不能放进 .reveal 包裹层—— 详情页正文本来也没有，安全）；吸附位置要避开 scroll-padding-top 已设的 5.5rem 页头高度。
预算
≈ 200 B CSS · 0 JS
收益
阅读体感的直接改善，也是「沉浸」而非「炫技」的那一类——适合放进面试讲解的取舍部分。
守卫影响
reading-contracts.mjs 会检查阅读页无横向溢出；吸顶头宽度需 min-width: 0 收敛，实测确认。

E6 · 页底「合上书」收束

P1 详情页页尾（可选延到首页）

滚到文章结尾时，让一枚装饰性的余烬柔光/封缄印记随 scroll(root) 的最后一段淡入，同时底纹网格略微隐去—— 给阅读一个「仪式性」的收尾，而不是文字戛然而止。

机制
新增一层 aria-hidden 的装饰 DOM，用相对 max scroll 的 scroll 时间线驱动 opacity；底纹复用 body::after， 在其 mask 上叠加滚动驱动的透明度。装饰层动 opacity 是允许的（不承载文字）。
预算
≈ 250 B CSS + 少量 DOM · 0 JS
收益
长文的「读完感」——把一次浏览变成一次有始有终的翻阅。
守卫影响
首页 HTML 余量约 9.6 KB，DOM 成本可忽略；装饰层必须 aria-hidden。

E7 · 阅读页左缘「羽毛笔」进度线

P2 详情页 reading-sheet

顶部那条横线继续保留，另在书页左缘加一条纵向余烬线，用同一份 scroll(root) 时间线驱动 scaleY—— 横向告诉「读到哪里」，纵向告诉「这一页有多长」，两条互为呼应。

机制
新增 .reading-ember，只动 transform；与横线共用同一时间线区间。
预算
≈ 200 B CSS · 0 JS
收益
书页的物理感；纯增量、可随时撤除。
守卫影响
不影响既有进度线断言（那是横线单独的 transform）。

E8 · 图版走廊横向视差 + 图鉴格错峰

P2 首页图版段 · /grimoire/

图版走廊内的图片随纵向滚动做轻微位移/缩放（廊本身仍是用户横向滑动）， /grimoire/ 的三格样品按序错峰入场。让展示页也有节奏。

机制
.rail-item .plate 用 view()； 图鉴格沿用 E1 的错峰手法。
预算
≈ 200 B CSS · 0 JS
收益
次要页面的完成度；成本极低。
守卫影响
保持走廊 overflow-x: auto 与内层滚动，不得撑宽页面—— 这是既有硬约束。

E9 · 序言滚动提示 + 底纹微视差

P2 首页 hero · body 底纹

首屏底部放一个 aria-hidden 的滚动提示（CSS 自走的箭头）， 在滚动 0→120px 内淡出；同时让 body::after 的方格纸随滚动做极小幅 translate，制造「纸在滑动」的视差。这是「半屏即退出」的第一印象信号。

机制
提示用 scroll(root) range 0…120px 控 opacity； 底纹是 fixed，加 transform 不参与布局。幅度要小到不引起眩晕。
预算
≈ 250 B CSS + 极小 DOM · 0 JS
收益
引导首次访客开始滚动，是全站「有交互」的第一个暗示。
守卫影响
reduce 下必须完全静态（箭头仍在，只是不动）。

五、落地顺序与依赖

顺序按「先零风险铺垫，再结构增强，最后跨页机制与打磨」组织。 同一阶段内各项互不依赖，可并行；跨阶段存在真实依赖，已在下面标出。

  1. 阶段 A · 零风险铺垫

    E1 → E2 → E3

    三项都是独立、纯 CSS、只读既有 token 的增强，改完可直接跑 pnpm assert:budgets 看余量。做完这一阶段，首页与详情页的滚动体感已经完全不同。

    依赖：无

  2. 阶段 B · 结构增强

    E5 → E6 → E7

    引入 sticky 章节头与阅读收束，涉及少量 DOM 与布局，需要连带跑浏览器验收 （横向溢出、sticky 生效、reduce 终态）。

    依赖：无（但与 A 共享预算，建议 A 先合并再估余量）

  3. 阶段 C · 跨页机制

    E4

    最高价值也最需要验证的一项。依赖首页卡片结构（slug 类名）已稳定； 必须同时新增浏览器断言，否则属于「写了没生效」。

    依赖：E1 的卡片结构稳定 → E4

  4. 阶段 D · 打磨

    E8 → E9

    次要页面与首屏细节，可在主体稳定后收尾。

    依赖：E1（复用错峰写法）

六、验收与守卫更新对照

这个仓库的规矩是：新增的每条承诺都要有检查盯着。多数滚动特效复用现有机制， 因此天然被既有断言覆盖；只有 E4 需要真正新增断言。

每项与守卫/验收脚本的关系
特效 被哪条既有检查覆盖 是否需新增断言
E1 卡片错峰 + 封面视差 verify-browser「每个 .reveal 收敛到可见终态（transform 归位、完全不透明）」 否（若封面视差动 opacity 则会破，务必只动 transform）

七、明确不做的项

以下方案在别处很常见，但在本仓库的约束下不值得做——列出来是为了避免反复讨论。

  • 全页 scroll-snap 吸附。中文长文按屏吸附会打断持续阅读，窄屏与触控板容易误触， 且与 scroll-behavior: smooth 和锚点跳转相互干扰。
  • 数字条 count-up 计数动画。需要 JS 定时器，而交互脚本 raw 只剩 351 字节—— 要做就得先瘦身别处，性价比低。
  • 目录 scrollspy 高亮。需要滚动监听。用 E5 的吸顶章节头替代， 零 JS 就能解决「读到哪一节」。
  • 正文/标题 opacity 从 0 渐入。违反对比度契约，且时间线未活跃时等于内容隐身—— 与本仓库「绝不落在中间态」的取舍直接冲突。
  • 给 sticky 元素祖先加 transform 的视差。会新建包含块并废掉吸附，属于硬红线。
  • 用 filter / mask 做图版「模糊显影」。 每帧重绘成本高，且对比度不可控；E2 用 scale + 描边已经足够。
